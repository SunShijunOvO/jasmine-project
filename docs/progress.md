### 2026-09-18 · 首张业务表创建与结构核验

- 学习者先区分共享 metadata 与数据库实际表，导入模型后通过 `Base.metadata.tables` 确认 `applications` 的五列和状态配置已登记。

- 数据库实际结构已确认：五列均存在且非空，`id` 使用序列默认值并由 `applications_pkey` 设为主键，状态列为 `character varying(18)`，存在名为 `application_status` 的 CHECK 约束。
- CHECK 当前列举的是 Python 枚举成员名（大写），而接口使用枚举字符串值（小写）；这符合 SQLAlchemy Enum 的默认持久化方向，但实际往返行为仍待首次 ORM 写入与读取验证。
- 学习者随后直接构造类型正确的 ORM 对象，将其加入 Session 并提交；数据库生成主键 `1`。关闭原 Session 后使用新 Session 按主键读取，文本、日期和状态均一致，状态被还原为 `ApplicationStatus.APPLIED`，枚举默认持久化的双向映射已验证。
- 这只是 REPL 中的持久化基础验证；临时 POST 路由仍只回显请求，F1 尚未通过 HTTP 完成。
- 后续已将请求级 Session、schema→ORM 转换、提交、刷新和 `ApplicationRead` 响应接入 POST。学习者通过交互文档提交合法记录，实际得到 201 与 `id=2`，响应字段和输入一致；POST 新增成功路径已完成 HTTP 验证。
